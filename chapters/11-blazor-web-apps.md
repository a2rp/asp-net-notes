# 11. Blazor Web Apps

## Component model

Blazor builds interactive web interfaces from reusable Razor components. A component combines markup, parameters, event handlers, and state. Unlike Razor Pages and MVC, where each request usually renders a new page, an interactive component can update part of the interface when its state changes.

The Blazor Web App template supports static server rendering and interactive render modes. Choose a render mode based on the interaction and hosting needs:

- Static server rendering returns HTML from the server without a live component connection.
- Interactive Server handles component events over a server connection.
- Interactive WebAssembly runs component code in the browser.
- Interactive Auto can use server interactivity first and WebAssembly after the client assets are available.

Each mode has different startup, latency, state, and deployment tradeoffs. Server interactivity uses a circuit associated with a client connection. WebAssembly code runs in the browser and must not contain server secrets.

## Enable Interactive Server

Register the server component services and map the render mode in Program.cs:

```csharp
builder.Services
    .AddRazorComponents()
    .AddInteractiveServerComponents();

var app = builder.Build();

app.MapRazorComponents<App>()
    .AddInteractiveServerRenderMode();
```

A component can opt into the mode:

```razor
@page "/counter"
@rendermode InteractiveServer

<PageTitle>Counter</PageTitle>

<h1>Reading list counter</h1>
<p>Items added: @count</p>
<button @onclick="AddOne">Add one</button>

@code {
    private int count;

    private void AddOne()
    {
        count++;
    }
}
```

If the render mode name is not in scope, add the appropriate RenderMode import in _Imports.razor. Follow the template generated by the installed SDK because it already includes the standard component setup.

## State and forms

Component fields hold state for that component instance. In Interactive Server, component state belongs to the server-side circuit. In WebAssembly, component state belongs to the browser process. Neither should be treated as durable storage. Save important changes through an application service and data store.

EditForm works with validation components such as DataAnnotationsValidator and ValidationSummary. Validate on the server as well when a command reaches an API or service. A hidden button or disabled UI control is not an authorization rule.

Use parameters for parent-to-child data, EventCallback for child-to-parent notifications, and injected services for application behavior. Keep components small enough that the rendered state and event handling remain easy to follow.

## Practice check

Create a counter component and test it with static rendering and Interactive Server. Notice that the static page has no live event handling until an interactive render mode is enabled. Then move the count into a scoped application service and compare what happens when the browser reconnects.

## Common mistakes

- Assuming every component is interactive by default.
- Putting secrets or trusted authorization decisions in WebAssembly code.
- Treating component state as a database.
- Performing slow synchronous work during event handling.
- Forgetting to enable the selected render mode in the host.
