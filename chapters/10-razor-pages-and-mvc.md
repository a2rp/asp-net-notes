# 10. Razor Pages and MVC

## Server-rendered pages

Razor uses HTML markup with C# expressions to render a response on the server. The browser receives HTML. A small interactive feature can use ordinary HTML forms or JavaScript; a server-rendered page does not require a single-page application framework.

Razor Pages organizes a page and its PageModel together. MVC separates controllers, views, and view models. Choose the shape that makes the application easy to understand. Both use routing, model binding, validation, dependency injection, and the same ASP.NET Core host.

## Razor Pages form

A page file can contain a post form:

```html
@page
@model CreateModel

<form method="post">
    <label asp-for="Input.Title"></label>
    <input asp-for="Input.Title" />
    <span asp-validation-for="Input.Title"></span>
    <button type="submit">Add item</button>
</form>
```

Enable the standard tag helpers in Pages/_ViewImports.cshtml:

```cshtml
@addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers
```

The PageModel receives the input and handles the request:

```csharp
public sealed class CreateModel(IReadingItemService service) : PageModel
{
    [BindProperty]
    public CreateReadingItemRequest Input { get; set; } = new();

    public async Task<IActionResult> OnPostAsync(
        CancellationToken cancellationToken)
    {
        if (!ModelState.IsValid)
        {
            return Page();
        }

        await service.CreateAsync(Input.Title, cancellationToken);
        return RedirectToPage("Index");
    }
}
```

A normal form generated by the Form Tag Helper includes an antiforgery token. Keep server validation even when client-side validation is enabled. Client checks improve feedback, but a caller can send a request without using the page.

## MVC shape

MVC uses a controller action to select data and a view to render it:

```csharp
public sealed class ReadingItemsController(
    IReadingItemService service) : Controller
{
    public async Task<IActionResult> Index(
        CancellationToken cancellationToken)
    {
        var items = await service.GetAllAsync(cancellationToken);
        return View(items);
    }
}
```

The default view path is Views/ReadingItems/Index.cshtml. Pass a view model that contains only what the page needs. Avoid using a database entity as a view model when that would expose persistence details or allow unexpected fields to be submitted.

## Choose a page model

Razor Pages works well when a page owns its request handlers and form state. MVC works well when several views are organized around a controller or the application already uses the controller pattern. Blazor is a different UI model with interactive components and is covered in the next chapter.

## Practice check

Create a page that lists reading items and a page that accepts a title. Try an empty title, a valid title, and a refresh after a successful post. Use the post-redirect-get pattern so reloading the result page does not repeat the form submission.

## Common mistakes

- Returning a page after a successful post instead of redirecting.
- Trusting browser-side validation without validating on the server.
- Putting persistence logic into the markup.
- Forgetting to show validation messages.
- Mixing Razor Pages, MVC, and Blazor concepts because they all use Razor syntax.
